# 01-contract-policy.md — 契約ポリシー

## このセクションの目的

利用規約（卸取引規約）、SLA、新規取引審査・契約変更・取引終了時のデータ取扱い、損害賠償・免責を定義する。**法務確認必須** 項目を多数含むため、最終確定前に弁護士レビューを受けること。本プロジェクトは SaaS サブスクリプションではなく **卸取引（BtoB）契約** であり、「エンドユーザー直販契約」「代理店契約」ではなく「取引基本契約 + 個別発注」の枠組みで記述する。

## 0-H. ハイブリッド編集ガイド（要点）

- 推奨モード: Human-first または Hybrid
- 人間確認必須: 法務表現、補償条件、データ返却・削除方針

---

## 1. 契約主体と種別

| 契約種別 | 対象 | 契約方式 |
| --- | --- | --- |
| 卸取引基本契約 | 新規取引申請が承認された取引先（Organization）| サイト上の利用規約への同意（クリックスルー）+ 個別発注ごとの取引条件 |
| 個別発注 | 取引先の発注 1 件ごと | 発注内容確認画面での同意（PRD-03 F-04-05）|

> クリックスルー同意の証跡は `applications.agreed_to_terms`（同意の有無）と `applications.agreed_terms_version`（同意した規約の版）の 2 列で残す（DEV-07 §5-1）。版を記録しない設計にすると、規約改定後に「契約成立時にどの条項に同意していたか」を立証できない（§5-2）。

---

## 2. 利用規約の主要条項

### 2-1. 提供サービスの定義

- 「[サービス名 `[Open: TBD-01]`]」とは、承認済み取引先に対して卸価格での商品発注を提供する BtoB 卸売サイトを指す
- 一般消費者向け販売・ゲスト購入は提供しない（INTAKE §7 取引形態。出典: 依頼者仕様書 §1・§4-1・§19）
- 取扱商品・卸価格は予告のうえ変更される可能性がある（BIZ-03 §5）

### 2-2. 取引先の責任

- 新規取引申請・会社情報・配送先情報等の入力内容が正確であること
- 卸価格・取引条件を第三者に開示しないこと（非公開情報の保護）
- アカウント情報の管理責任（ID / パスワード、担当者の異動時の速やかな連絡）
- 規約違反時は警告 → 取引停止 → 取引終了の 3 段階対応

### 2-3. 知的財産権

| 区分 | 取扱い |
| --- | --- |
| サービス本体（コード・UI）| 運営会社が保持 |
| 自社ブランド商品の画像・文章 | 運営会社が保持 |
| 他社メーカー・ブランド商品の画像・資料 | メーカーから提供されたもの、または使用許可を得たものだけを掲載する（依頼者仕様書 §18。許諾取得プロセスは GOV-02 TBD-12）。無断転載・改変を禁止 |

### 2-4. データの取扱い

| データ | 取扱い |
| --- | --- |
| 会社・取引先情報 | サービス提供目的のみ |
| 発注・決済履歴 | サービス提供・会計目的のみ |
| 操作ログ | サービス改善・障害調査目的 |
| 決済情報（カード番号）| 取得しない（決済代行事業者へ委託 — DEV-01 §2 参照）|

### 2-5. 禁止事項

- 違法行為への利用、第三者の権利侵害
- 卸価格・取引条件の第三者への開示・転売目的の悪用
- スパム的な大量アカウント作成、なりすまし申請
- リバースエンジニアリング、自動収集（商品情報のスクレイピング等）

### 2-6. 表現に関する取り決め

INTAKE §7 表現規制のとおり、医薬品的な効能を断定する表現（治る・改善する・治療できる等）を商品説明・診断結果に使用しない。利用規約にも、運営が提供する情報が医療的助言ではない旨を明記する。

商品説明は運営が管理画面から入力し（PRD-03 F-06-01）、診断結果の文言は開発者がリポジトリで管理する（DEV-06 §1-1）。**前者は入力時のレビューが効かない**ため、表現ガイドラインの周知と、公開前確認の運用で担保する（OPS-02）。

## 3. SLA（サービスレベル）

### 3-1. 稼働率

可用性の数値目標は **PRD-02 §5-2 を正本** とし、本書では値を再掲しない。

| サービス | SLA 上の取扱い | 計画停止除外 |
| --- | --- | --- |
| 公開サイト・マイページ・管理画面 | PRD-02 §5-2 の月間稼働率目標を参考値として提示（正式な補償契約は法務確認後に確定）| 該当 |

### 3-2. 補償

稼働率に応じた自動減額補償を設けるかは未確定 `[Open]`。当面は「重大障害発生時は個別協議のうえ対応する」方針とし、確定後に本節を具体化する。

### 3-3. サポート一次応答時間（本書が正本）

| 対応区分 | 一次応答 SLA |
| --- | --- |
| 新規取引申請の審査状況問い合わせ | 2 営業日以内 |
| 発注・決済関連の問い合わせ | 1 営業日以内 |
| その他の問い合わせ | 3 営業日以内 |

- 一次応答は平日 9:00〜18:00 ベースで計測する。時間外・休日の受付は翌営業日起算とする（OPS-02 §0 の対応時間原則と整合）
- 受付チャネル・エスカレーションの運用は OPS-02 §1 を参照

### 3-4. 計画停止

- 原則：月 1 回まで、土日深夜帯（日本時間 1:00〜5:00）
- 通知：7 日前にメール + マイページお知らせ
- 実施手順：OPS-02 §3

## 4. 新規取引審査・契約変更・取引終了

### 4-1. 新規取引審査

- 審査基準・却下理由の詳細は運営の裁量とし、対外的には「審査の結果、ご希望に添えない場合があります」旨のみを利用規約に明記する
- 審査完了までの目安期間は BIZ-02 KPI-03（申請審査リードタイム）を参照

### 4-2. 取引条件・卸価格の変更

| 変更内容 | 反映タイミング | 通知 |
| --- | --- | --- |
| 卸価格改定 | 改定日以降の新規発注から適用（発注確定済みの内容は不遡及。PRD-03 F-04-09）| 30 日前通知（BIZ-03 §5）|
| 支払条件変更 | 個別協議 | 都度通知 |

### 4-3. 取引終了時のデータ取扱い

| 状況 | データ保管 | 発注履歴の扱い |
| --- | --- | --- |
| 通常の取引終了 | 取引終了後 1 年間保持（PRD-02 §8）| 発注・決済履歴は会計目的で別途保持期間を適用（DEV-02 §8-1）|
| 取引終了 + 1 年経過 | 会社・取引先情報を物理削除 | 発注・決済履歴は会計上の保存義務期間まで保持 |
| 規約違反による強制取引終了 | 30 日後に会社情報を物理削除 | 同上 |

### 4-4. キャンセル・返品ポリシー（確定 — GOV-01 D-013）

最低発注金額（税抜 ¥10,000）・送料（全国一律税抜 ¥1,000、税抜 ¥30,000 以上で無料）・キャンセル期限（出荷前まで）・返品交換条件（破損・品質不良・誤配送時のみ、到着後 7 日以内連絡）は BIZ-03 §3 の通り確定済み。配送地域・配送会社（TBD-07）は引き続き未確定。

## 5. 価格改定・規約改定の運用

### 5-1. 価格改定

| 項目 | 方針 |
| --- | --- |
| 通知期間 | 30 日前にメール + マイページお知らせ |
| 既存発注 | 発注確定時点の価格を適用し、価格改定の影響を受けない（BIZ-03 §5）|

### 5-2. 規約改定（利用規約・プライバシーポリシー・特商法表示）

規約文面は**リポジトリ内のページに直書きで管理**する（DEV-06 §1-1、GOV-01 D-016）。管理画面から編集する仕組みは持たない。この選択の帰結として、改定の運用は次のようになる。

| 項目 | 方針 |
| --- | --- |
| 改定履歴の正本 | Git のコミット履歴（PRD-02 §8）。DB に版のレコードは持たない |
| バージョン表記 | コード内の定数 1 箇所で保持し、規約ページと申請フォームの両方が参照する（DEV-06 §1-1）。表記は改定日（例 `2026-09-01`） |
| 改定時の必須手順 | ①文面を修正 ②**バージョン定数を更新** ③法務レビュー済みの PR としてマージ ④デプロイ ⑤通知 |
| 通知期間 | 30 日前通知（重大変更は 60 日前）。§7 と同じ |
| 同意の証跡 | 申請時に `applications.agreed_terms_version` へ記録（§1、DEV-07 §5-1）。既存取引先への再同意取得の要否は **Open `[法務確認]`** |
| レビューの強制 | 管理画面が無いため、法務レビューを挟む場所は **PR レビューしかない**。規約文面を含む PR は法務レビュー済みであることを確認してマージする（DEV-03 §4、DEV-08 §6-2） |

> **文面だけ変えてバージョン定数を据え置くのが最も起こりやすい事故**である。そうなると、改定前後の取引先が同じ版番号で記録され、どちらの条項に同意したのか区別できなくなる。手順 ② を独立した項目として扱うのはこのため。

## 6. 損害賠償・免責

| 区分 | 方針 |
| --- | --- |
| 取引先の損害 | 直接損害に限り、当該発注の金額相当を上限とする方向で検討 `[Open: 法務確認]` |
| 間接損害 | 免責の方向で検討 `[Open: 法務確認]` |
| 第三者の権利侵害 | 取引先が責任を負う（自社が投稿・提供した情報に起因するもの）|
| 決済代行事業者の障害 | 免責 |
| 天災・通信障害 | 免責 |
